## Matriz de hallazgos

| id | componente | hallazgo | tipo | explicacion | evidencia (archivo:linea) | severidad | estado |
|---|---|---|---|---|---|---|---|
| H-API-01 | api | Token Base64 con secreto embebido y sin firma | Vulnerabilidad | El verificador ahora exige JWT HS256 firmado, `iss`, `aud`, `exp`, username y role, y lee una clave de `SECRET`. No se cierra hasta confirmar que el emisor externo entrega este contrato y despliega la variable de entorno. | api/app/security.py:10-40 | alta | Pendiente — verificacion implementada; falta confirmar integracion con el emisor JWT externo. |
| H-API-02 | api | El cliente puede elegir el owner de consultas y tareas | Vulnerabilidad | Listado y resumen comparan un `owner` no vacio con el username verificado; creacion rechaza un owner del cuerpo distinto. Las discrepancias reciben 403. El cierre queda pendiente hasta validar la integracion de identidad H-API-01. | api/app/main.py:55-88,90-104; api/app/services/task_service.py:8-11 | alta | Pendiente — control 403 implementado y probado localmente; depende de H-API-01. |
| H-API-03 | api | Filtros e inserts SQL concatenan valores | Vulnerabilidad | Los valores dinamicos de filtros, inserciones y lectura por ID se enlazan mediante placeholders SQLite; las pruebas cubren usernames con sintaxis SQL y texto con comillas como valores literales. | api/app/main.py:71-78,93-105,112-117; api/tests/test_api.py:55-77,104-120 | alta | Resuelto — consultas parametrizadas; regresiones locales para filtros e insercion pasaron. |
| H-API-04 | api | Carga de archivos usa el nombre del cliente sin limites visibles | Vulnerabilidad | Se normaliza el nombre para mantener el destino dentro del directorio, se limita la lectura a 5 bytes para imponer un maximo de 4, se permite solo `.txt`/`.pdf` y las colisiones guardan un nombre unico; errores usan 415/413 con detalle generico. | api/app/services/upload_service.py:6-54; api/app/main.py:106-116 | media | Resuelto — caracterizado y probado antes/despues; 415/413, limite, normalizacion y colisiones verificados. |
| H-API-05 | api | Rutas, persistencia y reglas concentradas en un modulo | Refactor | `create_app` configura SQLite y define las rutas; las funciones de ruta tambien contienen consultas y reglas, dificultando aislar responsabilidades y probarlas. | api/app/main.py:21-50,55-127 | media | Pendiente |
| H-API-06 | api | Tipado con diccionarios, excepciones amplias, anidamiento y logica repetida | Refactor | La respuesta de health ahora usa un modelo Pydantic y captura solo errores HTTP de urllib3, sin devolver detalles internos. Sigue pendiente separar persistencia y responsabilidades de las rutas. | api/app/main.py:142-158; api/app/schemas.py:47-52 | media | Pendiente — corregidos el acceso a la identidad y el error verboso de health; permanece pendiente la separacion de persistencia y otras mejoras de calidad. |
| H-API-07 | api | Evaluacion SCA de dependencias pendiente | Sugerencia | Los manifiestos fijan versiones de dependencias, pero el escaneo especifico Python no esta disponible en la herramienta configurada; se verifico PyJWT 2.15.1 con fuentes publicas, pero falta un escaneo reproducible de todo el entorno resuelto. | api/requirements.txt:1-6 | baja | Pendiente |
