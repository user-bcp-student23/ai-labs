# HU-01 — Integración del token de autenticación

## Origen
- **H-API-01 (api):** `api/app/security.py:10-40`. La integración queda pendiente de confirmar que el emisor externo entrega el contrato JWT requerido y que se configura `SECRET`.
- **H-API-02 (api, dependiente de H-API-01):** `api/app/main.py:55-88,90-104`; `api/app/services/task_service.py:8-11`. El control de identidad y propiedad está implementado y probado localmente; su cierre depende de validar la integración de identidad.

## Contexto
- La API verifica tokens JWT HS256, expiración, issuer, audience y claims obligatorios (`username` y `role`) mediante una clave configurada por variable de entorno.
- Falta confirmar la compatibilidad del emisor JWT externo y la configuración de `SECRET` en el entorno de despliegue.
- Las rutas de tareas ligan la identidad verificada al acceso; las discrepancias de propietario responden 403 según la matriz.

## Ajustes necesarios
- Confirmar con el equipo responsable del emisor que los tokens cumplen el contrato aceptado por la API.
- Configurar `SECRET` como variable de entorno en el entorno de integración/despliegue, sin incluir su valor en código ni evidencia.
- Validar de extremo a extremo el acceso protegido y el control de propietario usando la identidad proveniente del emisor.

## Criterios de aceptación
- Una prueba de integración con un token emitido por el emisor y compatible con el contrato permite acceder a una ruta protegida e identifica el `username` esperado.
- Pruebas de integración verifican que tokens expirados, con issuer o audience incorrectos, o sin claims obligatorios no autorizan el acceso.
- Una prueba verifica que solicitar tareas de un propietario distinto a la identidad verificada devuelve HTTP 403.
- La configuración de integración obtiene `SECRET` del entorno y las pruebas o evidencias no contienen tokens, secretos ni credenciales.

## Evidencia esperada
- Resultados de las pruebas de integración que cubran aceptación/rechazo de tokens y el caso 403 de propietario, identificados como **api — H-API-01 y H-API-02**.
- Evidencia de que `SECRET` está configurado como variable de entorno, sin registrar ni adjuntar su valor.
- Referencia al emisor probado y al entorno de validación, sin datos sensibles.
